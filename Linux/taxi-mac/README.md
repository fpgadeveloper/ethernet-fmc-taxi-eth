# taxi_mac — Linux network driver for the Taxi RGMII MAC

`taxi_mac.ko` is an out-of-tree Linux network driver for the `taxi_rgmii_mac`
block used by the Opsero *ethernet-fmc-taxi-eth* reference design. Each
Ethernet FMC port is one instance of the block — a Taxi 1G RGMII MAC, a Taxi
MDIO master and a small AXI4-Lite register file — paired with a Xilinx AXI DMA
(scatter-gather, 32-bit streams, DRE, no control/status streams). The driver
owns the MAC register file and the port's MDIO bus; the AXI DMA is driven
through the dmaengine API by the upstream `xilinx_dma` driver
(`CONFIG_XILINX_DMA`), so no DMA register access or interrupt handling lives
here.

One network interface is created per MAC instance (four for the Ethernet FMC).

## Device tree binding

```
taxi_rgmii_mac_0: ethernet@a0000000 {
    compatible = "opsero,taxi-rgmii-mac-1.0";
    reg = <0x0 0xa0000000 0x0 0x1000>;
    dmas = <&axi_dma_0 0>, <&axi_dma_0 1>;
    dma-names = "tx", "rx";
    phy-mode = "rgmii-rxid";
    phy-handle = <&phy0>;
    local-mac-address = [00 0a 35 06 21 05];
    mdio {
        #address-cells = <1>;
        #size-cells = <0>;
        phy0: ethernet-phy@0 { reg = <0>; };
    };
};
```

| property            | notes |
|---------------------|-------|
| `compatible`        | `opsero,taxi-rgmii-mac-1.0`; the driver also checks the ID register (`"TAXI"`) at probe. |
| `reg`               | AXI-Lite register window; only the first 0x50 bytes are used, the size may be 0x1000 or 0x10000. |
| `dmas`, `dma-names` | `tx` = the AXI DMA MM2S channel (`<&axi_dma_N 0>`), `rx` = S2MM (`<&axi_dma_N 1>`). |
| `phy-mode`          | Must be an RGMII mode. Use `rgmii-rxid`: the PHY adds the RX clock delay and the FPGA adds the TX delay. |
| `phy-handle`, `mdio`| The PHY sits on the port's own MDIO bus (Clause 22 only), registered from the `mdio` child node. |
| `local-mac-address` | Optional; a random address is used (and logged) when absent. |

The AXI DMA node is the one generated by the tooling for `axi_dma_N`
(`compatible = "xlnx,axi-dma-1.00.a"`, with `xlnx,include-sg`, both channel
subnodes carrying `xlnx,include-dre`). **The S2MM channel subnode must have
`xlnx,irq-delay` set to a non-zero value**, for example:

```
&axi_dma_0 {
    dma-channel@a0010030 {          /* xlnx,axi-dma-s2mm-channel */
        xlnx,irq-delay = /bits/ 8 <1>;  /* 8-bit! xilinx_dma ignores a 32-bit cell; 1 = 125 SG clocks = 1.25 us at 100 MHz */
    };
};
```

`xilinx_dma` programs the S2MM interrupt-coalescing threshold to the number
of descriptors pending when the channel (re)starts. With the 128-buffer
receive ring that means the completion interrupt would not fire until 128
frames had arrived; the delay-timer interrupt makes it fire shortly after
the last received frame instead. The driver warns at probe when the property
is missing or zero. It is harmless for the MM2S channel.

## Register-map dependency

The driver is written against register map v1.0 of `taxi_rgmii_mac`
(`Vivado/src/hdl/taxi_rgmii_mac.v`, VERSION register `0x00010000`):

| offset | register    | driver use |
|--------|-------------|------------|
| 0x00   | ID          | checked against `"TAXI"` (0x54415849) at probe |
| 0x08   | CTRL        | PHY reset pulse at probe; tx/rx enable on open/close; tx padding on |
| 0x0C   | STATUS      | in-band link speed exported as `mac_link_speed` |
| 0x10   | FLAGS       | W1C sticky error flags, polled by `ethtool -S` |
| 0x18/0x1C | TX/RX_MAX_LEN | wire frame length incl. FCS minus 1, programmed from the MTU |
| 0x20-0x34 | counters | read-and-clear, accumulated for `ethtool -S` |
| 0x40-0x4C | MDIO_*   | Clause 22 MDIO bus; MDIO_DIV = 19 (2.5 MHz MDC from a 100 MHz register clock) |

Data-path facts the driver relies on: the AXI-Stream frames carry no FCS in
either direction (the MAC appends it on transmit and strips it on receive),
bad-FCS/oversize frames are dropped by the MAC, the MAC has no address filter
(everything on the wire is delivered and filtered by the stack) and no
checksum offload, and the received length is what the S2MM channel writes
into the descriptor status, which `xilinx_dma` reports as the completion
residue (`length = buffer length - residue`).

## Building

Out of tree against a kernel build directory:

```
make KDIR=/path/to/kernel/build ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu-
```

`KDIR` defaults to `/lib/modules/$(uname -r)/build` for a native build on the
target. The Makefile also honours `KERNEL_SRC` and the `modules` /
`modules_install` targets, which is what Yocto's `module.bbclass` drives, so a
recipe only needs `inherit module` and `S` pointing at this directory. The
module was compile-tested against AMD linux-xlnx 6.12.40 (2025.2) for arm64.

## Using it

```
modprobe taxi_mac                 # or insmod taxi_mac.ko
ip link set eth1 up
ip addr add 192.168.1.10/24 dev eth1
ethtool eth1                      # PHY link settings (via phylib)
ethtool -S eth1                   # hardware counters, see below
ip link set eth1 mtu 8000         # jumbo frames, up to 8000
```

`ethtool -S` reports:

| name | meaning |
|------|---------|
| `rx_good`, `rx_bad` | frames delivered from / dropped by the RX FIFO |
| `tx_good`, `tx_bad` | frames transmitted / dropped by the TX FIFO |
| `rx_fifo_ovf`, `tx_fifo_ovf` | FIFO overflow events |
| `flag_tx_underflow`, `flag_tx_fifo_overflow`, `flag_tx_fifo_bad_frame`, `flag_rx_fifo_overflow`, `flag_rx_fifo_bad_frame`, `flag_rx_bad_fcs` | number of `ethtool -S` polls that found the sticky FLAGS bit set (the flag is cleared on each read) |
| `mac_link_speed` | link speed the MAC currently decodes from the RGMII in-band status (10/100/1000, 0 = unknown) |

The hardware counters are read-and-clear; the driver accumulates them into
64-bit totals so the values shown are monotonic. `ip -s link` shows the
driver's software counters (packets/bytes/errors/dropped per direction).

### MTU

Minimum 68, maximum **8000**. The MAC's TX and RX frame FIFOs are 8 KiB and
in frame mode a whole frame must fit in the FIFO (anything larger is dropped
as oversize), so the wire frame including VLAN tag and FCS is kept below
8192 bytes: 8000 + 14 + 4 + 4 = 8022. `TX_MAX_LEN`/`RX_MAX_LEN` are set to
`mtu + 22 - 1` so tagged frames pass at any MTU. Changing the MTU on a
running interface briefly pauses traffic while the receive ring is
re-allocated with the new buffer size.

## Design notes

- TX: one dmaengine `slave_sg` transaction per frame (non-linear skbs are
  linearised first), a 64-entry in-flight ring, queue stopped when the ring is
  full and woken by the completion callback.
- RX: 128 pre-allocated buffers of `mtu + 22` bytes, each an outstanding
  `DEV_TO_MEM` transaction. The completion callback queues the buffer and
  schedules NAPI; the poll routine delivers frames with `napi_gro_receive()`
  and re-arms each slot with a fresh buffer.
- Link management is phylib: `adjust_link` only logs, the MAC follows the
  RGMII in-band speed. The PHY reset line (CTRL bit 2) is pulsed at probe
  (20 ms low, 60 ms settle) before the MDIO bus is registered.
- Closing the interface disables MAC RX, waits for in-flight frames to drain,
  then terminates both DMA channels, so the DMA is not reset mid-frame.
- The DMA channels are requested on open and released on close. An AXI DMA
  soft reset (issued by `xilinx_dma` on terminate) resets both channels of
  the engine and `xilinx_dma` only re-enables a channel's interrupts when the
  channel is requested, so holding the channels across close/open would leave
  the MM2S channel without completion interrupts after the first close.

## Known limitations

- No checksum, segmentation or VLAN offload (GRO is done in software).
- The MAC has no address filter, so every frame on the wire crosses the DMA
  and is filtered by the network stack; multicast/promiscuous settings have no
  hardware effect.
- Clause 22 MDIO only; one PHY per port at the address given in the `mdio`
  node.
- Depends on `xilinx_dma` residue reporting for AXI DMA in SG mode (kernel 5.4
  or newer) and on `xlnx,irq-delay` (kernel 6.6 or newer, or linux-xlnx) for
  acceptable receive latency.
- Interface teardown while a DMA channel is wedged (`xilinx_dma` reports
  channel errors) requires a reload of the bitstream or a reboot; the driver
  logs the condition but cannot reset the AXI DMA itself.
